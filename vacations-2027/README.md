# Отпуска · Медсонар · 2027

Веб-приложение для планирования отпусков сотрудников на 2027 год. Интерфейс на русском языке, работает на компьютере и телефоне. Данные хранятся в SQLite на сервере, а не в браузере.

## Возможности

- Сотрудник входит по фамилии. Для однофамильцев дополнительно выбирает своё полное ФИО.
- Несколько периодов отпуска, подсчёт дней, черновик и отправка анкеты; сохранённую анкету можно исправить и отправить заново.
- Вопрос «Когда вы планируете работать в новогодние праздники?» с выбором дат с 31 декабря 2026 по 10 января 2027 включительно и комментарием.
- Отдельная вкладка отдела кадров: логин **admin01**, пароль **admin01** по умолчанию.
- Кадры видят статусы заполнения, даты отпусков, ответы о работе в праздники, могут выгрузить CSV для Excel, добавить сотрудника и изменить лимит дней.
- Импорт двух документов: выбранные фамилии из первого и полные ФИО из второго. Перед добавлением есть проверка совпадений. Неоднозначные совпадения не выбираются автоматически; повторный импорт сохраняет существующие анкеты.

## Список сотрудников

В список включены **73 врача** из переданного PDF: прежние 30 сотрудников сохранены, 43 добавлены в версии 1.0.2. Служебные профили кабинетов не включены. Прежние уточнения списка, включая **Николаенко Оксану Владимировну**, сохранены.

Архив и репозиторий содержат `private/initial-roster.json` только с необходимыми ФИО, с разрешения пользователя на размещение списка. При первом запуске он заполняет пустую базу; при обновлении один раз добавляет 43 новых врача, сохраняя существующие ID, ФИО, планы и лимиты дней. Для этого seed содержит версию и отдельный список добавлений. Исходные PDF и XLSX и другие персональные данные из них в приложение не включены. Живую базу и ключи сессий в Git не добавляйте.

Для развёртывания полного актуального списка сохраните включённый `private/initial-roster.json`. Если его не переносить, новая база останется пустой. Через вкладку кадров можно отдельно импортировать пары документов (выбранные фамилии и полные ФИО) или добавлять сотрудников вручную. Поддерживаются XLSX, CSV, TXT, DOCX и PDF с текстом, максимум 10 МБ на документ.

## Запуск Python

Нужен Python 3.12.

```bash
python -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.lock
.venv/bin/gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 --timeout 60 'app:create_app()'
```

Проверка готовности: HTTP-запрос `GET /healthz` должен вернуть `{"status":"ok","year":2027}`. Приложение обслуживает страницу `/` и сохраняет анкеты между перезапусками процесса.

## Размещение в облаке

Для выбранного пользователем Render есть отдельная [пошаговая инструкция](RENDER.md).

Нужен хостинг, который запускает Python или Docker, предоставляет HTTPS и **постоянный диск**. Для SQLite запускайте один экземпляр приложения с общим диском; не используйте несколько независимых реплик и эфемерное хранилище.

### Docker на сервере

Распакуйте архив и выполните:

```bash
docker compose up -d --build
```

Приложение слушает порт 8000, данные сохраняются в томе `vacations-data`. Для доступа через домен настройте у хостинга HTTPS-прокси к порту 8000 и задайте `COOKIE_SECURE=1`. Пересоздание контейнера сохраняет данные; удаление тома их удалит.

### Render

Включён `render.yaml` для Docker Web Service с постоянным диском 1 ГБ. План `starter` и диск являются платными ресурсами Render: их создание выполняется владельцем аккаунта. Создайте Blueprint из своего **закрытого** репозитория или перенесите эти настройки в Web Service; в секретном поле `ADMIN_PASSWORD` задайте `admin01`, если требуется именно этот пароль. После успешного развёртывания Render выдаёт публичный HTTPS-адрес сервиса. Публикация рабочей среды Codex сама по себе не создаёт публичный адрес приложения.

При запуске из Git приватный начальный список не переносится автоматически — используйте загрузку документов через раздел кадров. При запуске Docker из архива список включён и загрузится автоматически в новую базу.

### Настройки

| Переменная | Назначение |
| --- | --- |
| `DATA_DIR` | Каталог постоянного диска; по умолчанию `instance/` рядом с приложением. |
| `PORT` | HTTP-порт, по умолчанию `8000`. |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | По умолчанию оба `admin01`. |
| `APP_SECRET_KEY` | Ключ подписи сессий; если отсутствует, приложение один раз создаёт файл `.session-key` в каталоге базы. Не менять между перезапусками. |
| `COOKIE_SECURE` | `1` для облачного HTTPS, `0` для локальной проверки по HTTP. |

Сотрудникам доступна только собственная анкета, кадрам — общая сводка. Вход по фамилии реализован согласно запросу: знание чужой фамилии позволяет открыть её анкету. Для кадров используется пароль; запросы изменения данных защищены CSRF, сессии подписаны, попытки входа ограничиваются.

## Подсчёт отпуска

Начальная норма — 28 дней; кадры могут изменить её индивидуально. Нерабочие праздничные дни РФ по ст. 112 ТК РФ (1–8 января, 23 февраля, 8 марта, 1 и 9 мая, 12 июня, 4 ноября) исключаются из дней отпуска. Обычные и перенесённые выходные включаются. Периоды не могут пересекаться или выходить за 2027 год; для отправки один из периодов должен включать не менее 14 дней отпуска. Не требуется расходовать весь лимит. Это сбор пожеланий сотрудников: отправка анкеты не означает утверждение графика или назначение работы в праздники.

## Проверки

```bash
.venv/bin/python -m pip install --require-hashes -r requirements-dev.lock
.venv/bin/python -m pytest -q
```

Тесты используют вымышленные данные и отдельные временные базы. База сотрудников и их ответы не изменяются. Для ручной проверки в браузере: вход по фамилии → сохранение черновика → отправка → выход → кадры → просмотр и экспорт.

При установленном системном Chromium доступна полная браузерная проверка:

```bash
.venv/bin/python tests/browser_smoke.py
```

Она запускает отдельный сервер и временную базу, проверяет однофамильцев, сохранение после обновления страницы, отправку, работу в праздники, кадровую сводку, изменение лимита, импорт и экспорт, мобильную вёрстку. Скриншоты с вымышленными данными сохраняются в `test-results/`.

Текущая версия прошла 65 автоматических тестов и браузерные сценарии через Waitress и Gunicorn. Проверены границы праздничного периода, сохранение ответов и обновление списка существующей базы без потери ID, анкет и исправлений кадровика. Публичное развёртывание веб-сервиса не выполнено: для него нужен выбранный хостинг и доступ к аккаунту.

## Резервные копии

Копируйте базу через SQLite Backup API, чтобы сохранить согласованность при работающем сервере:

```bash
.venv/bin/python scripts/backup.py /путь/к/резервной-копии.sqlite3
```

Файл копии содержит персональные данные сотрудников и ответы; храните его в закрытом месте. Для восстановления остановите приложение, восстановите копию в `DATA_DIR/vacations.sqlite3` и запустите приложение. Вместе с существующими файлами `-wal`/`-shm` восстанавливать старую копию нельзя: переместите старую базу с её служебными файлами в отдельный каталог перед восстановлением.
