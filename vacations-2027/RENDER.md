# Как разместить «Отпуска 2027» на Render

Комплект подготовлен для Render. Публичный сервис пока не создан, платные ресурсы не заказаны. После запуска Render выдаст HTTPS-ссылку, которую можно отправить сотрудникам.

## 1. Загрузите приложение в закрытый репозиторий GitHub

Распакуйте `vacations-2027.zip`. Создайте **приватный** репозиторий GitHub и загрузите в его корень содержимое папки `vacations-2027`, чтобы `render.yaml`, `Dockerfile` и `app.py` находились непосредственно в корне.

Для автоматического заполнения списка включите также **`private/initial-roster.json`**. В нём находятся 30 согласованных ФИО: Николаенко Оксана Владимировна включена, Корсакова, Растрыгина и Соломонов исключены. Исходные документы загружать в репозиторий не нужно.

`private/` исключён из обычного Git-добавления, чтобы ФИО не попали в открытый репозиторий случайно. При загрузке через сайт GitHub добавьте эту папку вместе с остальными файлами. Если используете Git, **только после проверки, что репозиторий приватный**, добавьте этот конкретный файл явно:

```bash
git add -f private/initial-roster.json
```

Если не хотите хранить ФИО в репозитории, оставьте `private/` вне Git. Приложение запустится с пустым списком; затем заполните его через вкладку отдела кадров: импорт двух документов добавит 29 однозначных совпадений, после чего вручную добавьте **Николаенко Оксану Владимировну**. Три исключённые фамилии импорт не добавит, поскольку в PDF для них нет совпадений.

## 2. Создайте Blueprint

Откройте [панель Render](https://dashboard.render.com/), выберите **New → Blueprint** и подключите свой закрытый репозиторий. Укажите ветку с приложением. Render прочитает `render.yaml`.

Конфигурация содержит:

- Web Service `medsonar-vacations-2027`, запуск из Dockerfile;
- план **Starter** и **постоянный диск 1 ГБ** — это платные ресурсы, итоговую стоимость показывает Render перед созданием;
- диск, смонтированный в `/var/data`, для базы и ключа сессий;
- проверку готовности `/healthz`;
- защищённые cookies для HTTPS и автоматически создаваемый ключ сессий.

В поле **ADMIN_PASSWORD** введите **`admin01`**. Логин `admin01` уже задан в конфигурации. Проверьте ресурсы и запускайте развёртывание в своём аккаунте.

Не выбирайте бесплатный сервис без постоянного диска: он не гарантирует сохранение ответов сотрудников после перезапуска.

## 3. Проверьте приложение

Когда сервис перейдёт в состояние **Live**, откройте HTTPS-адрес из карточки сервиса.

1. Вкладка **Отдел кадров** → логин `admin01`, пароль `admin01`. Если начальный список включён, должно быть **30 сотрудников**, без заполненных анкет.
2. Выйдите и откройте вкладку **Сотрудник**. Введите, например, фамилию **Николаенко**: должно отображаться ФИО **Николаенко Оксана Владимировна**.
3. Отправьте сотрудникам адрес сервиса. Они смогут выбрать периоды отпуска на 2027 год и рабочие дни 1–8 января.

Для проверки сохранения можно создать собственный черновик и убедиться, что он остаётся после обновления страницы. Не отправляйте вымышленные пожелания от имени сотрудников в рабочую базу.

## Эксплуатация

Оставляйте один экземпляр сервиса, подключённый к этому диску. Перезапуск или новое развёртывание не перезаписывают существующую базу начальным списком. Не удаляйте диск: на нём находятся ответы. Используйте резервные копии диска у Render и периодическую выгрузку CSV из отдела кадров. CSV удобен для работы с графиком; полную базу сохраняет SQLite Backup API, описанный в `README.md`.

## Сохранённая рабочая среда Codex

В настройках этой рабочей среды сохранены `install_script` и `start_skill`: установка зависимостей с проверкой хешей, тесты и запуск сервера. Для сохранения подготовленной среды проверьте и сохраните изменения в её настройках, затем опубликуйте среду. Эта публикация сохраняет среду разработки; публичный сайт для сотрудников создаётся отдельно в Render по шагам выше.
